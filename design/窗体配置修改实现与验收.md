## 使用方式

从「系统配置 → 窗体配置修改」进入。输入对象类名称或标签并选择搜索结果，选择关联窗体及 Body。

- 左侧列表包含隐藏控件和未绑定 Property 的装饰控件。双击对象类属性或基础控件可以新增，也可以拖入画布。
- 画布支持 Ctrl 多选、空白框选、拖动和 50%–200% 缩放。首个选中控件标记为基准；横排对齐只统一 Y，不改变 X。
- 右侧修改控件配置；点击空白处修改 Form 标签、宽高。输入框在回车或失去焦点时提交到草稿，HTML 多行输入在失去焦点时提交。
- 新增 HTML、图片、分组和嵌套窗体时填写对应内容/来源。容器中的新增控件使用容器内坐标。BL 的原生 Image/Nested Form 使用属性绑定；独立静态图片通过工具箱保存为 HTML 图片控件。原生 Nested Form 绑定 Item 属性，右侧窗体选择用于切换关联窗体的只读预览，运行时窗体由 Aras View 决定。系统若提供独立来源属性，则按元数据保存该属性。
- 删除含子控件的分组时明确列出整组范围；删除暂存在草稿中，可撤销。
- 点击「变更摘要」查看差异，点击「保存修改」写回。切换窗体、Body、刷新、导航和关闭窗口时检查未保存修改。
- 原「窗体配置」用于生成窗体；现在可输入 Form 高度，默认 350。新编辑器读取实际高度，不自动重置已有窗体。

## 数据和保存约定

独立的 `IFormConfigurationEditService` 查询 ItemType/View/Form/Body/Field，不调用原生成服务的覆盖逻辑。Core 编辑模型保存原始 XML、原值和独立变更字典。通过 `language="*"` 读取全部语言作为冲突检查基线；事件、多语言标签、未知属性保留，XML 使用 `XElement` 构造。

控件枚举和可编辑属性从当前系统 Field/Form/Body 的 Property 元数据和 List Value 读取。未确认的属性不写入；已有未知类型和自定义颜色不被自动归一化。现有控件名称、Property 绑定和 Form/View 关联不修改。

保存前检查连接、完整原始快照和 Form 锁。不同系统/数据库/账号不能提交旧草稿；同一目标重连时重新加载元数据并核对服务器快照。Form 使用 `update`，避免 `edit` 动作自动解锁。取得的锁在 finally 释放，用户原有锁保留。输入和新增名称按目标系统 `stored_length` 校验。

单次 AML 内按已有 ID 编辑、增加和删除 Field；仅在缺少 Body 且新增控件时创建 Body。已有 Body 不删除、不重建。新增 ID 在草稿中固定；响应丢失后先读取服务器核对，不盲目重试。确认写入后记录逐项操作日志，已核对的重复提交不会重复记日志。保存结果重新读取后更新草稿基线。

原生成请求新增可选 `FormHeight`：WinUI 显式传入默认 350 或用户值，未传值的历史调用继续自动计算。HTML 边框高度保持原布局计算，独立于 Form 高度。

## 预览边界

WebView2 的外层页面只管理选择、坐标和消息；原 HTML/CSS 放在不允许脚本的 sandbox iframe 中。原事件不执行，不提交业务表单。HTML 活动元素和事件属性从预览副本移除，不改写服务器原始 HTML。

支持常用输入控件、标签、按钮、列表、HTML、图片、分组和只读嵌套窗体。嵌套引用检测循环，内层不参与当前窗体编辑。静态/相对定位控件不自动转换为绝对定位；跨容器组合不执行拖动与对齐。

图片、CSS 和字体只代理读取当前服务器 Client 路径下的静态资源，不转发密码/令牌、不跟随重定向；需要单独浏览器认证或来自其他站点的资源显示预览限制。高级 CSS 可呈现但不提供源码编辑。动态脚本、部分特殊控件和响应式窗体不保证与运行时视图相同；响应式窗体禁用写入。

## 2026-09-09 画布白板修复

用户截图中对象类和控件读取正常，但中央连画布底纹及提示都未显示。对应 12:04:55、12:05:09 的工具箱错误日志记录 `EnsureCoreWebView2Async` 抛出「找不到指定的模块」。原生宿主在普通构建下复现；检查 PE 头确认输出的 WebView2 WinRT Core 为 I386（x86），而进程运行在 x64。WebView2 包对 AnyCPU 默认选择 x86 原生资产，浏览器脚本回归及 XBF 编译均无法发现这类错误。

WinUI 默认显式使用 x64，保留显式 x86/ARM64 目标支持，普通构建路径不变。页面单独维护画布加载、失败及重试状态；资源缺失、导航失败、脚本异常或启动超时显示原因并记录错误日志，查询对象类不会覆盖中央提示。重试仅重载画布，保留已读取配置、草稿与撤销记录。窗口关闭时使用已缓存的窗口对象并及时释放页面，避免关闭期间空引用及异步渲染访问失效组件。

新增原生宿主以真实 WinUI 页面检查默认构建的 DLL 架构、控件呈现、错误提示、重试、资源缺失、握手超时及窗口关闭。BL 库不存在截图中的 `IC_Project_Plan_Review` 对象类，因此另外使用该库 `Part cc` 的只读配置快照（34 个控件、784 × 300）验证画布；不修改业务窗体，原生测试禁止保存。

最终验证：25 项服务回归、11 项浏览器回归及 7 项原生宿主检查通过。普通 WinUI 构建成功、XBF 已生成，交付目录中应用与 WebView2 Core 的 PE 架构均为 AMD64。只读快照测试不加载外部资源，因此其截图中的样式表缺失提示属于测试限制。
