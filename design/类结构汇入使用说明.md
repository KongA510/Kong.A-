# 类结构汇入使用说明

## 功能目标

“系统配置 → 类结构汇入”用于把 Excel 中的多级分类路径组装成 Aras `ItemType.class_structure`。每次执行都是全量覆盖，不会把新模板与旧类结构合并。

## 使用步骤

1. 登录 Aras，在“系统配置”中打开“类结构汇入”。
2. 点击“下载汇入模板”。
3. 在模板的“类结构”工作表中填写路径；每一行代表从第1级到末级节点的一条完整路径。
4. 回到页面选择已填写的 `.xlsx` 文件，检查唯一节点数、最大深度、树形预览和名称调整提示。
5. 输入对象类名称或中英文标签进行模糊查询，选择一个 ItemType。
6. 点击“覆盖并汇入类结构”，在二次确认框中核对目标对象类和节点数。
7. 汇入成功后，关闭 Aras 中已打开的对象类页面并重新打开，检查类结构；可以继续修改对象类或分类并保存。

## 模板规则

- `路径序号`、`备注`只用于阅读，不参与组装。
- `第1级`至`第10级`表示真实 class 节点，最多支持10级。
- 同一行必须连续填写层级，中间不能留空。
- 相同父级下的同名节点会合并；同名但父级不同的节点会分别创建。
- 同级节点的显示顺序按模板中首次出现的顺序决定。
- 不要把目标 ItemType 名称写进模板。以 `Document` 为例，第1级直接填写“模组”或“芯片”。
- 节点名称最长128个字符；完全重复的路径会忽略并在预览中计数。
- Aras 的半角 `/` 是分类路径分隔符，不能作为单个节点名称的一部分。工具自动转换为全角 `／`，例如 `芯片/单管` → `芯片／单管`，保持为一个节点；预览、确认框、完成提示和操作日志都会说明调整。
- 如果同一父级下同时填写 `芯片/单管` 和 `芯片／单管`，转换后会重名。工具在写入前报出行号和层级，要求调整名称，避免静默合并两个不同节点。

## 示例

| 路径序号 | 第1级 | 第2级 | 第3级 |
|---:|---|---|---|
| 1 | 模组 | TR1 | 产品需求分析说明书 |
| 2 | 模组 | TR2 | 软件概要设计 |
| 3 | 模组 | TR2 | 硬件概要设计 |
| 4 | 芯片 | 01.MRD | 产品需求评审单 |
| 5 | 芯片 | 01.MRD | 市场分析报告 |

组装结果的结构如下：

```xml
<class id="目标 ItemType 的 ID">
  <class id="新 GUID" name="模组">
    <class id="新 GUID" name="TR1">
      <class id="新 GUID" name="产品需求分析说明书" />
    </class>
    <class id="新 GUID" name="TR2">
      <class id="新 GUID" name="软件概要设计" />
      <class id="新 GUID" name="硬件概要设计" />
    </class>
  </class>
  <class id="新 GUID" name="芯片">
    <class id="新 GUID" name="01.MRD">
      <class id="新 GUID" name="产品需求评审单" />
      <class id="新 GUID" name="市场分析报告" />
    </class>
  </class>
</class>
```

无名称根节点使用目标 ItemType ID；每个子节点调用 `Innovator.getNewID()`。写入目标字段固定为 `class_structure`，通过 IOM `setProperty` 作为 XML 字符串传输。发送前和回读后均校验根节点、唯一有效 GUID 及分类名称，再比较保存结果与本次生成的 XML。

## 覆盖注意事项

- 覆盖前请确认目标对象类。工具只允许单选，避免一次误改多个 ItemType。
- 旧 `class_structure` 不会自动备份或保留；需要回退时，应先在 Aras 侧导出或记录原值。
- 若写入或回读校验失败，页面会显示原因并写入错误日志；成功写入会记录敏感操作日志。

## 2026-09-15：汇入后对象类无法保存的原因与修复

### 官方资料核对

1. [Aras 官方论坛：Update class_structure with AML?](https://www.aras.com/community/f/development/55324/update-class_structure-with-aml/10550) 的已验证答复指出 `class_structure` 是 Text 字段，XML 应作为字符串（例如 CDATA）写入；其导出示例中无名称根节点 ID 与 ItemType ID 相同。工具原先的 `setProperty` 传输方式正确，但根节点不应重新随机生成。
2. BL 环境部署随附的 Aras 官方客户端 `Client/scripts/ClassStructureDialog.html` 加载 `Client/javascript/include.aspx?classes=ArasModules,ClassReferencesStructure,TearOffMenuController,ClassStructure`。其中 `ClassStructure.ValidateClassName` 明确拒绝空名称及包含半角 `/` 的名称，`GetClassPath` 用 `/` 拼接层级。这个规则应同时用于模板汇入。

### BL 实测结论

使用连接池中的 BLPLM 环境建立独立的临时 ItemType，完成后清理。没有覆盖现有 Document、Part 或其他业务对象类。

| 场景 | 实测结果 |
|---|---|
| 普通名称、随机根 ID | 汇入和后续保存都能成功；不能单凭根 ID 不同断言空引用原因 |
| 旧逻辑汇入含 `芯片/单管` 的节点 | 首次汇入成功，类结构可以读取 |
| 对上述对象回读后执行正常 `edit` 保存 | 重现 `Object reference not set to an instance of an object.` |
| 仅修正根 ID、保留非法节点名称 | 仍然失败 |
| 修复后的正式 `ImportAsync` 重新汇入同一原始 Excel | 自动改为 `芯片／单管`，无名称根使用目标 ID；成功恢复 |
| 恢复后修改普通属性、重命名分类、新增分类、回读核验 | 全部成功 |

此案例确认的直接问题是旧工具绕过了分类名称校验，允许半角 `/` 进入单个节点；不是缺少一张需要额外建立的分类关系表。根 ID 同时按照官方导出格式修正。

### 已汇入异常结构的恢复步骤

1. 启动更新后的 WinUI 工具箱，登录需要修复的 Aras 环境。
2. 关闭 Aras 中已经打开的异常对象类页面，避免缓存旧结构。
3. 在“类结构汇入”选择原来的完整 Excel，不必手工把名称中的 `/` 改掉。
4. 确认预览中的名称调整，例如 `芯片/单管` 变为 `芯片／单管`，并选中原目标对象类。
5. 执行“覆盖并汇入类结构”。这是全量覆盖，子节点会使用新 ID；仅编辑原有非法节点或只改根 ID 无法替代此步骤。
6. 重新打开 Aras 对象类，修改并保存，核对结果。

本功能只更新类结构定义；若业务数据或分类专用窗体、属性、生命周期已经引用旧名称，名称调整后也需核对这些已有分类路径，工具不会自动改写它们。

### 回归验证

`tests/ArasToolkit.ClassStructure.RegressionTests` 使用真实 R37 IOM 和替代传输层，覆盖预览与实际写入一致、XML 字符串传输、名称冲突、GUID、重复覆盖、十级路径、异常回读及取消后的审计。BL 实测另行覆盖旧错误复现与正式服务恢复后的二次保存。
